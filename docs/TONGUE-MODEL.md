## 0. 现状：距离基已拆成两层（后续实测，优先于 §3）

本文初稿写于「舌面 10 坐标直接当距离基」之时。此后跑通了三道闸门
（`gate_retrieval.py`、`fit_metric_full.py`、`audit_loco_features.py`），
结论与初稿不同，**以本节为准**。

### 0.1 距离度量跑在哪一层：已改判

```
18 维几何层  merged_basis.json   **距离度量实际跑在这里**
10 维摘要层  summary_basis.json  已弃用，见下
```

**这一节在 2025 年被推翻过一次，理由要留着。** 最初的拆法是：几何层只负责解释，
摘要层负责距离，因为把派生轴 `constriction_pos` 加进几何层同一向量时，拟合权重在
9 个折里一次都没给它实质权重——它是同一向量内舌面坐标的函数，共线，优化器绕开它走。

**但这个理由只证明「优化器不需要它」，不证明「它没有信息」。** 后来逐符号审核时量到：

```
tools/audit_modifier_collisions.py，同一基音上不同修饰符的碰撞对
基线                     维数   轮廓碰撞   基线碰撞    丢失
merged_basis.json         18      2412      219   -2193   ← 零丢失
summary_root.json         12      2412     1265   -1147
summary_basis.json        10      2412     3689    1277
```

`atr`/`rtr` 只动舌根，摘要层没有舌根坐标，施加后向量**逐位相同**——不是精度损失，
是信息归零。补回 `root_x/root_y` 后，Gate 1 部位格与清浊误取一分未变，LOCO 0.4986 →
0.5027。**代价为零**，于是补回。剩下 tip/blade/dorsum 的问题是同一回事，只是补不补
已经不影响主结论：完整几何零丢失。

**教训：把「优化器给它零权重」读成「它没有信息」，是我这一轮犯的第三次同类错误。**
优化器只说明**在那个目标函数下**不需要，不说明**没有**。

摘要 10 维：`constriction_pos, constriction_gap, lip_open, lip_round,
velum, lateral, larynx, periodic, source_tilt, duration`。**已弃用**：丢 1277 个
同基音修饰符区分对，133 个基音全部受损。

**选轴的判据（J6）：一根轴必须对每个音素都有同一个定义。** 凡是「对
元音取 A、对辅音取常量」或「对辅音取 A、对元音取常量」的轴，一律不收——
那是手调的类别特判，与最初的 `place` 链是同一类错误，只是缩小到了
一个坐标上。这条判据是本轮踩坑换来的，见 §0.5 最后一条。

### 0.2 部位轴不再手调

`derived_constriction` 早已算出收缩部位，但只被记成标签 `site_from`。
现在它进向量了，**与它声称描述的几何不可能脱节**——改舌面，部位轴自动跟着动。

修复生成器缺陷后实测分布为 **derived 48 / assigned 82 / none 3**，`none` 只剩
`h ɦ ʔ`（确实没有口腔收缩）。部位序列现已严格递增：

```
0.00 双唇 → 0.05 唇齿 → 0.10 齿 → 0.18 齿龈 → 0.25 龈后
→ 0.28 卷舌 → 0.30 龈龈 → 0.36 硬腭 → 0.45 软腭 → 0.52 小舌
→ 0.70 咽 → 0.80 会厌
```

### 0.3 实测成绩（`retrieval_gate.json`）

**两处都要说清楚，不要只报好看的那个。**

**部位/手法格**：几何层 0.3696 低于摘要层曾经的 0.5217，高于旧基线 0.2391。但
**这个比较曾经被我做错过一次**：我当时拿几何层的**未拟合**数字去比旧基线的**已拟合**
数字，得出「压缩赢了」的结论，再据此差点压掉全部舌面坐标。唯一交叉验证过的拟合指标
是 LOCO，两者在 0.5037 / 0.5027 上是**打平的**。取舍的依据应当是 LOCO 加修饰符覆盖，
不是 Gate 1 的原始几何距离。

**LOCO 0.6488 → 0.5089**：**这个差距是假的，已查实。** 旧表 16 根轴里有 11 根在某一类

**同一判据下新基线略胜。**

### 0.4 修掉的一个真缺陷

`f` `v`（脣齿擦音）曾被判为「无收缩」——`CONSTRICTOR['labiodental'] = None`
表示没有**舌**收缩部位，但脣齿音收缩得和双脣一样紧。它们被塞进哨兵值，
与 `h ɦ ʔ` 同格，清浊格因此从 1.000 塌到 0.111。给唇类收缩补上明确
位置后，部位格由 0.174 升到 0.3696，摘要层再升到 0.5217。

### 0.5 两条被证伪的假设（留档）

- **全度量能追平对角度量**（`fit_metric_full.py`）：不成立。同折同参数下
  差距由 0.164 扩到 0.172，且两边都变差——78 个参数对 53 个训练符号的
  过拟合。对 18 维几何层证伪，对 10 维摘要层未测。
- **补一根舌位高可救 `high`**：不成立。部位格由 0.522 跌到 0.304，
  `high` 召回仅由 0.084 到 0.126。
- **保留两根声门轴可救 `tense`**：不成立。`tense` 召回 0.500 → 0.487。
  `diagnose_tense.py` 随后证明**整个方向打错了目标**：PhonoLib 标 `tense`
  的 17 个音素**全是元音**（`e i j o u w y ø ɘ ɤ ɥ ɨ ɯ ɰ ɵ ʉ ʍ`），
  此处的 `tense` 是高元音，与 `high`/`back`/`round` 共现，**与喉部收紧无关**。
  当初按 r = −0.775 合并声门轴，错在没看相关性的符号；后续拿 `tense` 当
  合并的佐证，则是错在特征本身。
- **`vowel_height` 能救元音特征**（`summary_vheight.json`，已弃用）：数字上
  成立——`tense` 0.500 → 0.618、`high` 0.084 → 0.189、LOCO 0.4986 →
  0.5318，且 Gate 1 的部位格与池化 hit@1 **完全不变**。**仍然弃用**：
  该轴对元音取舌高、对辅音取常量，是类别特判，不合 J6。收益只在 LOCO
  一个指标上，而 Gate 1 用真人数据看不到任何改善——**说明买到的
  0.033 来自对制表约定的拟合，不是来自生理**。

### 0.6 `strident`：**量不存在，且在本音位表内不可检验**

`strident` 在当前基线上是 0.000。查过了，不是度量找不到，是这个量压根没建。

`tools/audit_strident.py` 逐轴量「咝音 vs 非咝音擦音」的可分性，`blade_y` 的
Cohen's d 高达 **3.902**、单轴 1-NN 准确率 1.000。但这个 d 是假的：

```
部位          咝音              非咝音擦音
alveolar      s z               —
postalveolar  ʃ ʒ              ɧ          ← 全表唯一的同部位对照
palatoalveol  ɕ ʑ              —
retroflex     ʂ ʐ              —
其余八部位     —                全部在这里
```

**全表唯一的同部位咝音度对照是 `ɧ` 一个符号。** 咝音全在齿龈/龈后/龈龈/卷舌，
非咝音擦音全在唇、齿、硬腭、软腭、小舌、咽。所以 `blade_y` 的 d=3.9 量的是**部位**，
不是咝音度——咝音与部位在这份音位表里近乎共线。

只看那唯一诚实的对照 `ʃ ʒ` vs `ɧ`：

```
18 根轴里 16 根完全相同，只差 periodic 与 source_tilt（即清浊）
tip_x blade_x dorsum_x constriction_pos constriction_gap  全部逐位相等
```

**所以 `strident` 在模型里不存在，且无法用本仓数据检验。** 加一根咝音度轴在原理上
可行（那是真实的声学量，不违反 J6），但要验证它只能拿 `ʃ ʒ vs ɧ` 这一个 n=3 vs n=1
的对照，或者用 PhonoLib 的 `strident` 标签当答案——后者是拟合答案键，循环。

**结论：这是一条待补的缺口，不是当前可以修的缺陷。** 补它需要独立测量的噪声谱数据，
本仓目前只有 7 个辅音音位（`fetch_consonant_data.py`，Phatak 与 BDPA 均缺席，
PhoneticBank 不可达）。

同类的还有 `low`（旧基线清洗后 0.000、新基线 0.125）——元音高度与辅音高度在
`dorsum_y` 上大量重叠（100 个辅音里有 48 个落在元音高度区间 0.190–0.348 内），
一根均匀定义的舌高轴在原理上就无法把「低元音」与「低辅音」分开。这不是实现问题，
是 J6 的必然代价：**要求一根轴对每个音素同一定义，就必然放弃那些本质依赖音类别的区分。**

### 0.7 LOCO 差距的构成：**那 0.140 不是信息，是作弊**

按特征维拆解后，旧基线的优势集中在**元音特征**：`high` +0.326、
`front` +0.210、`back` +0.197、`tense` +0.276、`consonantal` +0.185。

于是去查旧表这 16 根轴在类内的方差（`tools/audit_j6_axes.py`）：

```
axis                  元音sd  辅音sd  类内常量
place                 0.0000  0.4940  ← 元音全体常量
lips_closed           0.0000  0.3024
tip_shape             0.0000  0.3092
vel_open              0.0000  0.2862
lateral_ratio         0.0000  0.2713
glottal_tension       0.0000  0.1889
larynx_height         0.0000  0.3720
duration              0.0000  0.4743
jet_focus             0.0000  0.3396
airflow_direction     0.0000  0.6000
tongue_root           0.2002  0.0000  ← 辅音全体常量
```

**16 根里有 11 根在某一类内部是常量。** 把这 11 根剔掉再跑 LOCO：

| 基线 | 维数 | LOCO act_prec |
|------|------|--------------|
| 旧基线，全轴 | 16 | 0.6488 |
| **旧基线，按 J6 清洗** | **5** | **0.5040** |
| 新几何基线 | 18 | **0.5089** |

**那 0.140 全部来自类内常量的轴。** 剔掉之后旧基线掉到 0.5040，**比新基线还低
0.005**。

**为什么这是作弊而不是信息**：一根类内常量的轴不是轴，是**免费的按类别偏移**。
它把整类音素一起挪动、类内不分辨任何东西，却让度量零成本地分开元音与辅音。
`place` 对 33 个元音是同一个值，`tongue_root` 对 100 个辅音是同一个值——
它们编码的不是解剖，是「这是不是元音」。

**这正是 J6 判据要排除的东西**，也是当初拒绝 `vowel_height`（对元音取值、
对辅音取常量）的同一个理由，只是这次长在旧基线里。旧基线不是更准，
是更宽松。

**剩下的真实差距**：清洗后新基线 0.5089 对旧基线 0.5040，**新基线略胜**。
所以「LOCO 落后 0.140」这句话本身应当作废——从来没有一个在同一判据下落后的比较。
文档此前一直引用 0.6488 作对照，是拿一个作弊基线当基准。

### 0.8 迁移到 C 运行时：一次静默损坏的家族

本节记录 18 维基线接入 `vec4ipa` / `vec2ipa` 时做的事与查出的缺陷。

**迁移是数据更换加一次语义搬迁，不是换一张表。** `spec_next.scheme` 经
`gen_vectors_h.py` 生成 `src/vectors.h`，这一步早就是生成式的；但新基线里
**没有** `body`、`lips_closed`、`tip_shape`、`effective_oral_area` 这些量。
按「取值集合相同」试过加别名，结果不可用：`voiced`、`vel_open`、`lateral_ratio`
全是二值轴，会互相匹配上（如 `voiced` 匹配 `velum`），那等于把「不支持」
悄悄变成「支持但含义不同」。真正能安全对应的只有 4 根
（`voiced→periodic`、`vel_open→velum`、`lateral_ratio→lateral`、`duration→duration`），
`place` 虽是同一个物理量但刻度不是仿射关系（±0.90 对 0.00–0.95），改个名接不上。
**结论：只能把修饰符从「旧轴上的符号翻转」重写成「舌面轮廓上的位移」。**

#### 0.8.1 修饰符：13 条标量规则此前从未生效

`clamp_cfg` 用 6 个键**重建**配置字典，`velum`、`lateral`、`periodic`、`larynx`、
`source_tilt`、`duration` 全部被丢掉。标量修饰符写进去的值当场被扔掉，
`nasal`、`long`、`short`、`half`、`extra_short`、`syllabic`、`unrel`、`raised`、
`lowered`、`rnd_more`、`rnd_less`、`nasal_rel`、`lat_release`、`nasal_click`
**13 条全是空操作**。

这个缺陷藏得住，是因为行为看起来完全正常——向量照出，只是什么都没变。
`tools/audit_modifier_visibility.py` 只查了 `DISPLACE` 的 13 条舌面位移，
所以一直没照出来。修法：`clamp_cfg` 把非舌体字段原样带出。

**这是行为变更，不是纯移植。** 若此前引用过 `tongue_modifiers.json`，数值已变。

#### 0.8.2 一类四次出现的静默损坏

四次缺陷同一个根因：**把编译期常量 `NDIM` / `DIM_*` 当成运行时状态用**。

| 位置 | 后果 | 是否静默 |
|------|------|----------|
| `dim_of_ok` 回退到枚举下标 | 修饰符写进完全不同的坐标 | 是 |
| `-s` / `--weights` 按 `NDIM` 循环 | 18 维下只打印前 16 维 | 是 |
| `--metric` 按 `NDIM` 解析 | 第 17、18 维交叉项被丢弃 | 是 |
| scheme 写数字码而非名字 | 133 行全部加载失败 | 否（会报错） |

后三个正好藏掉 `constriction_pos` 与 `constriction_gap`——整个重设计最关键的两根轴。

**为什么 395 项既有测试一次都没抓到**：它们全部跑在编译进的 16 维 scheme 上，
而 `NDIM == g_ndim == 16`。**编译期常量恰好等于运行时值**，这一整类缺陷在默认
配置下数学上不可观测。测试验的是「编译进的那个 scheme 能否工作」，从来不是
「任意 scheme 能否工作」——而本次工作的意义正是换 scheme。

因此新增两条检查（已接进 `make test`）：
`tools/test_tongue_contour.py`（C 与 Python 逐位对照）与
`tools/test_scheme_portability.py`（逐个 scheme 文件核对报告维度数、轴名顺序、
权重条数、向量宽度，并断言宽度不符的度量文件被拒绝而非截断）。
后者的有效性是**证过的**：故意把 `g_ndim` 改回 `NDIM` 重编译，
只有舌面 scheme 那一项失败，正是这四次缺陷的判定特征。

#### 0.8.3 接线的两处非显然之处

1. `ModRec` 按**函数指针**分派（`apply_voicing_mod` 比对 `m->apply`），
   不是按名字。名字在第三个初始化位，但改用函数指针比对可免去改动 ~180 条
   位置初始化。
2. **tier 未改**。`TIER_PLACE < TIER_MANNER < TIER_TIMING` 的先后保持原样，
   所以「拼写重解析得到同一个向量」成立；变的只是每一步**做什么**。

送气、送气弱化、上标族（`ʰ ˞ ²ᵐᵖᵗ`…）在轮廓里没有对应量，**刻意留在轮廓之外**：
它们走旧轴并在加载舌面 scheme 时告警。硬塞进轮廓会违反 J6——一根轴的含义
不能因音类而异。

#### 0.8.4 一个值得记的正确行为

`tˤ` 的 `constriction_pos` **不动**，这是对的：`t` 的收缩点在齿龈且 gap=0，
`ˤ` 移动的是舌根，舌根不会因此比已闭合的齿龈更紧。
`kˤ`（软腭基，收缩点在舌背）才会让站点移动。
即：**派生轴只在被移动的部位成为最紧处时才跟随。**
我最初写的断言假定「任何舌面位移都带动站点」——那等于断言一个 bug。

### 0.9 反向重建：新基线**更差**（与 §0.3、§0.7 方向相反）

Python 侧三道闸门（Gate 1、Gate 3、LOCO）都偏向新基线。但 C 侧逆拟合
（`vec2ipa`）在同一任务上给出相反结果。取各基线**自身真值向量**加等幅噪声、
按段名精确重建：

| 基线 | σ=0.01 | σ=0.02 | σ=0.05 |
|------|--------|--------|--------|
| 旧 16 维（自身手调权重） | — | **133/133** | — |
| 旧 16 维（均匀权重） | — | **133/133** | 125/133 |
| 新 18 维（导出权重 0.64–1.0） | 113/133 | 110/133 | 92/133 |
| 新 18 维（`constriction_pos`/`gap` ×30） | 112/133 | 106/133 | 78/133 |

**两个对照把别的解释排掉了**：

1. *不是度量权重的问题*——旧基线换成均匀权重仍是 133/133；反过来把新基线的
   `constriction_pos`/`gap` 权重提到 30，结果**更差**（σ=0.05 时 92→78）。
   均匀度量对旧基线毫无损失，对新基线也提不上来。
2. *不是逆拟合没接上*——旧 scheme 下 `vec2ipa` 正确要求 16 个值，新 scheme 下
   正确接受 18 个并精确重建零距离样本。

**看得见的失效模式全是「邻近段」**：软腭 `ɡ`→`ɢ`、鼻音 `ŋ`→`ɴ`、擦音 `sʼ`→`tʼ`、
清擦 `fʼ`→`pʼ`。软腭 0.45 与小舌 0.52 相距 0.07，塞音与擦音的差别主要在
`constriction_gap`（0.00 对 0.14）——都是**相邻坐标上的小差值**，恰好落在噪声量级。

**这与 J6 的代价是同一件事，只是换了个位置显现。** J6 要求一根轴对每个音素同一定义，
代价是旧基线里那些**类内类别事实**（`lips_closed`、`tip_shape`、
`glottal_tension`、`airflow_direction`）不再有专属轴，而被压成几个连续坐标之间
的细小差值。旧基线在这类任务上占便宜，靠的是一根轴只区分两个远点。

**结论必须分任务说，不能合并成一个「更好」**：
按 PhonoLib 特征召回与人类混淆检索衡量（§0.3、§0.7），新基线更好；
按**反向精确重建**衡量，新基线明显更差（σ=0.02 时 0.812 对 1.000）。
本节之前没有这一栏，因为此前从未在 C 侧量过逆拟合。

**未解决**：这个差距是否可以通过改几何缩小，尚未实验。**但要注意那可能正是 J6
不允许的方向**——把某根轴按音类改成类别专属，就退回到 §0.7 判为作弊的那类轴。

#### 0.9.1 追下去的结果：瓶颈不是噪声，是 32 个符号共用同一个向量

拆开 23 个失效看，**19 个的对���段在表里与另一段逐位完全相同**。逆拟合无法
分开向量相同的两个符号，所以无论换什么度量都到不了 133/133。最初 16 组：

```
c == ǂ    k == k͡p    p == ʘ    q͡χ == χ    sʼ == tʼ
t == ǁ    t̪ == ǀ    x == k͡x    kʼ == xʼ    l == ɮ    ŋ == ŋ͡m    ǀ == t̪
```

**根因是一处填错轴**：`periodic`（周期性）这根轴被填成了旧表的 `voiced`（清浊），
于是 click 的气流感随 `airflow_direction` 一起被丢掉。`ǂ == c`、`ʘ == p`、
`ǁ == t`——双唇塞音与双唇 click 无法区分，这不是度量问题。

改法：`periodic` 按轴名本义取值，click（`airflow_direction = -1`）记 0，
其余记 1。**对每个音素同一定义**——元音与口腔辅音同取 1，不违反 J6。
清浊没有丢，它本来就在 `larynx` 上。

**重复组 16 → 12**，click 全部与口腔同部位段分离。Gate 1 `hit@1` **0.3696 → 0.3906**。

**但反向重建没有跟着好**（σ=0.02：110→108；σ=0.05：92→86，在噪声量级内）。
诚实结论：**那 19 个失效不是被重复卡住的，真正卡住的是剩下 4 个真失效**
（`fʼ→pʼ`、`t͡ʃʼ→tʼ`、`ɨ→ɤ`、`θʼ→tʼ`）。修 click 是对的，但它不在这条路径上。

剩余 12 组里有一类值得单独盯：**塞音与其同部位的塞擦音**
（`k == k͡p`、`ɡ == ɡ͡b`、`q͡χ == χ`、`x == k͡x`）。这与本仓早前量到但一直没
写进文档的「塞擦音只差 3 根轴」是同一件事，现已确认为**向量完全相同**。

#### 0.9.2 度量不是杠杆：逐轴权重扫描

§0.9.1 的问题留下的是「能否缩小差距」。实测**不能靠调度量**：

```
均匀权重                       108/133
tip_x x8                       112/133   ← 单轴最佳
larynx x8 / lateral x8         111/133
constriction_gap x8            107/133
constriction_pos x8            107/133
duration x8                    106/133
velum x8                       104/133
```

18 根轴逐一放大 8 倍，最好只到 112，且多数轴**变差**。差距不在度量分配上，
在几何本身。

#### 0.9.3 按可达上限归一后的诚实对比

新基线有 24 个符号与他人向量逐位相同，可达上限只有 121。归一后：

| σ | 旧 16 维 | 新 18 维 |
|---|---------|---------|
| 0.01 | 133/133 = **1.000** | 111/121 = 0.917 |
| 0.02 | 133/133 = **1.000** | 108/121 = 0.893 |
| 0.05 | 119/133 = 0.895 | 86/121 = 0.711 |

**归一后差距缩小但没有消失**：σ=0.02 时新基线仍只达到自己上限的 89%。

四个真失效的逐轴差异全部 ≤0.15，且集中在少数几根轴上。最刺眼的是
`fʼ` vs `pʼ`——**摩擦音与塞音只差 `constriction_gap` 0.10**：

```
fʼ vs pʼ   tip_y +0.030  blade_y +0.040  lip_open +0.150
           constriction_pos +0.050  constriction_gap +0.100
```

**方式在这个基线里由很小的坐标差承担**，而旧基线有 `effective_oral_area`
与 `jet_focus` 两根专门吃这个信息的轴。这与 §0.9 开头是同一件事，
现在有了具体数字：J6 的代价在**辅音方式**上比在**部位**上更重。

#### 0.9.4 重复的真正来源：分类器缺一个分支（已修一半）

§0.9.1 剩下的重复不是「同部位相邻段天然难分」，是**分类器漏读了两类信息**。
`classify()` 从头到尾**没读过 `airflow_direction`**，也没有 click 这个方式；
而 `dur == 0.0 → stop` 排在 `jets > 0 → affricate` 之前，把带喷流特征的
塞擦音抢走了。

修后（`tools/gen_tongue_table.py`）：加 click 分支（`flow < 0`），
把 `lat`、`jets` 两项都提到 `dur == 0` 之前。`ǀ ǁ ǂ` 现判为 click。

**但 `k͡p` 与 `ɡ͡b` 修不了——信息在源表里就不存在**：

```
k   vs k͡p   仅 lips_closed 不同：0.000  vs  1.000
ɡ   vs ɡ͡b   仅 lips_closed 不同：0.000  vs  1.000
t   vs t͡s   duration 0.000/1.300、jet_focus 0.000/0.950、eoa 0.000/0.100
```

`t͡s` 靠三根轴正常区分；`k͡p`/`ɡ͡b` 只在 `lips_closed` 上不同，而那个值是
**错的**——它们是唇化的软腭/声门塞擦音，旧表把「唇化」记成了「双唇闭合」。
所以这两个符号既丢了塞擦音方式、又把部位说成了双唇。轮廓生成器补不出
源表没有的信息；要么先修旧表，要么把这两个符号排除在新基线之外。

另记：`ɺ`（卷舌闪音）在旧表里 `lateral_ratio = 1.0`，分类器据此判成 lateral，
与 `l ɮ` 合并成三向重复。这是**旧表的另一处错标**，同样不是本层能修的。

**净结果**：重复组 12 → 11，可达上限 121。Gate 1 `hit@1` 维持 0.3906，
133 符号六项检查 0 问题，全套 1635 项测试通过。

#### 0.9.5 元音退步的实测（**前一版结论已推翻，见 §0.9.6**）

33 个元音上测两两最近距离：

```
old 16-dim   最近 0.0500   中位 0.9766
new 18-dim   最近 0.0000   中位 0.9013
```

真正碰撞的只有两对：`w == ɥ`（两者圆唇）、`ɔ == ʌ`（两者不圆唇）。
`ɔ` 的 `lip_round` 是 0.00，而它是圆唇元音——旧基线靠
`lips_rounded`（0.950 对 0.000）把二者分开，轮廓里 `lip_round` 取代了那根轴
却没有把圆唇信息带过来。这是**圆唇信息的丢失**，已确认为缺陷。

`ɔ` / `ʌ` 之外的中位距离下降（0.9766 → 0.9013）说明整体点云略收紧，
但没有成对碰撞，暂不单独追。

#### 0.9.6 `place = 0` 的兜底把符号静默塞进 `ə`（§0.9.5 初版的真因）

初版把「多个符号共用 `(0.35,0.30)`」当成元音网格过粗，**那是错的**——
那几个符号里有一半根本不是元音。真因在 `gen_tongue_table.py` 的取值分支：

```python
no_place_gesture = abs(place) < 1e-9 and tip_shape < 0.5
if no_place_gesture:
    dx, dy, lr = VOWEL_CFG.get(seg, (0.35, 0.30, vec['lips_rounded']))
```

**兜底值 `(0.35, 0.30)` 正是 `ə` 的坐标。** 命中该分支的共 8 个符号：

```
in VOWEL_CFG      25 个
DEFAULT (schwa)    8 个：j w ə ɥ ɪ ɰ ʍ ʏ
```

其中 `ə ɪ ʏ` 是**真元音但不在元音表里**（`ɪ` 近闭合、`ʏ` 近闭合圆唇，
现在都拿到中央元音的高度）；`j w ɥ ɰ ʍ` 是**辅音**，旧表给它们的 `place` 是
0（近音/擦音的中性值），于是被当成元音处理。

两点后果：

1. `VOWEL_CFG` 只有 25 条而元音有 30 个以上，**缺的 3 个被静默填成 `ə`**；
2. 5 个辅音走了元音轮廓路径，拿到它们并不该有的中央元音形状。

与本日其余若干缺陷同族：**兜底而不是失败**。`VOWEL_CFG.get(...)` 的默认值
让缺失变成了静默错误。修法分两块——补 `ə ɪ ʏ` 的坐标（属模型作者工作），
以及把 `j w ɥ ɰ ʍ` 从该分支里排除（按辅音处理，坐标可由部位锚点给出）。
**待决项**：排除条件该用什么判据。旧表里这五个与真元音在
`place`/`tip_shape` 上完全相同，唯一可分的候选是 `lateral_ratio`
（只有 `l` 是 1.0，此处为 0.0，无区分力），因此**现有旧表里可能没有任何
轴能把它们和元音分开**，需要先确认再定。

## 2. 坐标系

### 2.1 矢状面框架（`gen_tongue_model.py` 头注）

```
x  前 → 后。0 = 上齿之后（切牙后方），1 = 咽壁
y  绝对高度。0 = 静息舌面，1 = 接触腭顶
```

舌体离散为 **4 个部分**，每部分一个 `(x, y)`：`tip / blade / dorsum / root`。
`y` 是**绝对**高度，不是到腭顶的比例——因为腭顶本身不平（§2.2）。
`roof(x) − y` 就是**间隙**，`gap = 0` 为接触。

**为什么是 4 个点而不是一条样条**：`tools/gen_groove.py` 测过——腭沟是
~1.5 cm 的局部特征，样条会把沟深和 blade/dorsum 高度耦合起来，压低沟会顺手
移动收缩点。所以沟是**第五个控制点**，不是样条节点。

### 2.2 腭参考曲线 `roof(x)`

`PALATE_KNOTS` 10 个节点，节点间线性插值。这是整个模型唯一**承重**的解剖输入：
没有它，"导出的部位"只是把作者手填的坐标换个说法。

| x | y | 说明 |
|---|---|------|
| 0.00 | 0.95 | 上齿之后 |
| 0.10 | 0.62 | 齿龈嵴（腭顶向牙下降） |
| 0.18 | 0.85 | 龈后 |
| 0.32 | 1.00 | 硬腭最高点 |
| 0.45 | 0.86 | 软腭 |
| 0.55 | 0.60 | 悬雍垂 |
| 0.62 | 0.15 | 腭咽口（**无顶**） |
| 0.70 | 0.62 | 咽壁 |
| 0.80 | 0.78 | 下咽 |
| 0.90 | 0.45 | 喉 |

节点值是**解剖描述**，本仓无影像数据核验，标 `[假设]`。
它承重的后果是可测的：龈后接触发生在 y=0.925、硬腭接触发生在 y=0.925
（`palatal` 锚点 dorsum y = 0.925 = roof(0.25)），两者高度差 0，属实测。

### 2.3 物理尺度换算（`gen_groove.py`）

模型的 x 与 y **不可通约**，距离比较前必须换算。采用的换算及其依据：

- `cm_per_x_unit = 19.44`（17.5 cm 声道 / 0.90 有效 x 跨度）
- `cm_per_y_unit = 3.03`（1.0 cm 口腔高度 / 0.33 的 y 跨度）

两个常数都锚在文献常见值（成人男声道 17–18 cm、腭顶到舌底 ~1 cm），
并**同时给出模型原生单位**的同一批数字，以便换算改变时结论仍可复核。
`tools/data/tongue_groove.json` 里每个距离都有 `hausdorff_cm` 与 `model_units`
两栏，这是有意的。

| 坐标 | 含义 | 由什么定它 |

  唯一达到"接触"的部位值**，因此 `blade_y` 同时是闭合紧度轴。
- `dorsum_x` / `dorsum_y`：元音四边形 25 个点的外包络
  （x 0.22–0.44，y 0.16–0.62），加上软腭 0.45/0.86、小舌 0.52/0.678。
- `root_x`：静息 0.72，只有鼻音/边音的 `−0.04` 前移、咽 0.70、会厌 0.80、
  喉 0.66 四种取值——**只有 4 个 distinct 值，这是 `root_x` 得 C 的直接原因**。
- `root_y`：静息 0.25 到会厌 0.78。
- `lip_open` / `lip_round`：`[0,1]` / `[−0.5, 1]`。`lip_round` 下界取 −0.5
  而非 −1，因为 −1 只在 `i`（0.50 展唇）这一个音上出现，再放宽没有语料支撑。

### 3.2 颌/唇/喉的三坐标替换（`tract_parts.json`，`gen_tract.py`）

旧 `lip_open` 是**复合量**：下颌带动下唇，并通过舌骨上肌群带动喉，
所以它对元音编码的大部分其实是颌运动，而颌运动是 F1 的直接驱动。
拆成：

| 坐标 | 范围 | 依据（`range_basis` 字段自报种类） |
|------|------|------------------------------|
| `jaw_open` | [0, 1] | `JAW_RANGE_MM = 45`，**LITERATURE**：成人最大切牙间距离 35–50 mm 取中。取生理极值是为了让 `jaw_open = 1.0` 是**可达状态**，否则归一化轴上的每个值都是凭口味定的比例 |
| `lip_aperture` | [0, 1] | `LIP_RANGE_MM = 20`，**ASSUMED**：颌固定时唇仍能分开的量。本仓无任何数据记录唇张开毫米数 |
| `larynx_height` | [−1, 1] | `LARYNX_RANGE_MM = 20`，**LITERATURE**：喉位升降约 2 cm |

派生常数：

- `JAW_LIP_TRANSMISSION = LIP_RANGE_MM / JAW_RANGE_MM = **0.444**`（DERIVED）。
  这是拆分真正依赖的那一个数，`main()` 把它从 0.25 扫到 0.75：
  需要夹紧 jaw 坐标的段数从 **21/133 变到 58/133**。**拆分是方向性的，不是精确的。**
- `JAW_LARYNX_TRANSMISSION = 0.5`（**ASSUMED**）。舌骨/喉不是刚性挂在颌上的，
  但只有部分颌行程变成喉下降。本仓无喉位数据，此系数不可拟合。
- `MANDIBLE_RADIUS_MM = 90`（LITERATURE，切牙到髁突），用于把切牙张开量换算成
  旋转角，使口底位移是弦/竖直分解而不是猜的。最大旋转角实测 **28.96°**。
- 静息声道 `REST_TRACT_MM = 175`（LITERATURE，17–18 cm 中值），
  分段 90 / 65 / 20 mm 是 **ASSUMED**（`ORAL_REST_MM` 等）。

三坐标对 133 段全部有值。往返检验：拆分后重组恢复旧 `lip_open`，
**133 段轮廓差 0，最大残差 1.11e−16**。**这个 0 是算术的**——拆分与重组是
互逆的，它只证明没有东西漏进舌坐标，不是分离正确的证据。

### 3.3 未定：喉位坐标的家

`gen_tongue_table.py` 把喉位作为**方式档案字段**（`larynx`，3 个取值，
**不参与距离**）；`gen_tract.py` 把 `larynx_height` 列为**距离坐标**。
两处尚未统一，本文不假装它已经统一。

### 3.4 非距离的随行字段（3 个）

`velum`（0/1，2 取值）、`lateral`（0/1，2 取值）、`duration`（0.10–1.00，7 取值）。
它们随行携带以吸收方式与时长，但**不属于 10 维距离基**。旧表里对应
`vel_open` / `lateral_ratio` / `duration`。

### 4.2 收缩点的导出（J4 的落点，也它的破口）

```python
gap = roof(x) − y     # 四个部分各算一次
best = argmin(gap)
if lip_open <= 0.05 and best.gap > 0:  best = (0.0, 0.0, 'lips')
```

闭唇压过任何舌部位——双唇闭合是全声道最闭的事件，而且它根本不是舌动作。

`derived_site()` 加了一道**经验门**：如果没有任何部位落在 `roof` 的 0.05 之内，
说明没有收缩可导出，位点退回锚点指定值。理由写在代码注释里：
开放手势的收缩部位离腭顶 0.45，而静息的舌根离咽壁只有 0.40，
不设这道门，"离腭顶最近"会对每个开放手势都返回舌根。

**实测三分解**（修复后）：`derived` **48** / `assigned` **82** / `none` **3**（仅
`h ɦ ʔ`）。即 J4 只在 **36%** 的行上真正成立，82 行（62%）的收缩点仍是**参数**
而不是几何。

修复前的分布是 57 / 66 / 10，差在两处，两处都是真缺陷（详见 `docs/SYMBOL-AUDIT.md`）：
唇部锚点原会落到静息舌根（gap 0.402），使 `/p̪/ /ʔ/` 这两个塞音没有闭塞；`assigned`
分支的 `x` 与 `gap` 取自不同器官。

### 4.3 修饰符：位移而非符号翻转（`gen_tongue_modifiers.py`）

旧方案把协同调音写成共享轴上的符号翻转（腭化 = `body +0.24`、软腭化 =
`body −0.12`、唇化 = `body −0.12` 然后靠 `lips_rounded` 硬撑开）。
这里每条修饰符是**轮廓的位移向量**：哪个部分、往哪、移多少。

**13 条舌面位移**：`palatalized / velarized / labialized / pharyngeal /
atr / rtr / advanced / retracted / dental / laminal / apical / centralized / midcent`
**13 条标量规则**：`nasal / nasal_rel / lat_release / nasal_click /
raised / lowered / rnd_more / rnd_less / long / half / extra_short /
syllabic / unrel`

> 计数以文件为准：**13 + 13 = 26**，不是交接摘要里写的 14 + 14。
> 两处计数不一致时以 `tools/data/tongue_modifiers.json` 的键数为准。

位移的三种写法（`=` 绝对落点 / `~` 向中心缩放 / 裸 dx,dy 增量）分别对应
"命名一个区域"（dental）、"向中心靠"（centralized）、"给一个方向"（rtr）。
`clamp_cfg()` 保证结果物理：x ∈ [0.02, 0.90]，y ∈ [0, roof(x)]。

**实测检验一：旧方案的条件分支全部消失**。5 条记录在案的旧分支
（`OLD_CONDITIONALS`：`dental` 看 `lips_closed`、`advanced`/`retracted` 看
`place` 与 `tip_shape`、`rnd_more`/`rnd_less` 看 `lips_rounded` 中段）
现在都不需要分支——位移本身不需要分支，标量规则是单调 +/−。

**实测检验二：13 条位移向量两两可分**。78 对，**0 对精确碰撞**。
在 `t` 上最接近的一对是 `centralized / midcent`，d = **0.0100**；
换底音后最小值：`t` 0.0100、`s` 0.0100、`k` 0.0400、`ʈ` 0.0849
（`advanced / apical`）。**这些是轮廓单位下的裸欧氏距离，未经度量加权，
也不代表声学可分性**——但 0 碰撞是可复现的事实。

**实测检验三：双重调音由两条修饰符叠出来**，脚本打印四例的落点
（`k͡p`、`ŋ͡m`、`tʲ`、`ɧ`）。这是"结构性支持"的演示，不是声学验证。

### 5.1 F3 是唯一的非循环拟合：R² = 0.690

`tools/fit_tongue_forward.py`，9 个 phonTools 元音语料
（pb52 h95 t07 f73 p73 b95 f99 a96 y96），回归**在语料内去均值**
（加语料哑变量 + 截距），所以九种语言之间的声道长度差不会被读成舌运动。

| 共振峰 | n（语言×元音格） | R² | RMSE | 性质 |
|--------|----------------|-----|------|------|
| F1 | 73 | 0.9134 | 45.2 Hz | **循环** |
| F2 | 73 | 0.9120 | 159.9 Hz | **循环** |
| **F3** | **63** | **0.690** | **108.0 Hz** | **诚实的那个** |

覆盖 16 个 IPA 元音符号、9 种语言。

**F1/F2 的 R² 是循环的，必须当作不存在。**舌坐标是从 IPA 元音梯形手写出来的，
而那个梯形**本身就是 F1/F2 的几何**；用这些坐标回归 F1/F2，是从 F1 推出 F1。
脚本的 docstring 与每一行输出都标了 `CIRCULAR`，本文照抄这个标签。

**F3 不是。**建模时没有任何一处参照过 F3：坐标编码的是舌在哪、多高，
那是 F1/F2 的信息。如果 F3 仍被预测出来（R² = 0.690，RMSE 108.0 Hz），
说明这个表示携带了它从未被给过的元音质量信息。**这是"表示有效"的证据，
不是"参数正确"的证据。**

### 5.2 唇块在元音上确实可分离（唯一由共振峰测量支撑的结论）

`gen_tract.py`，用项目自己的圆唇配对规则（同一 IPA 图格、只差唇）：
**9 对、跨 6 种语言**（f73 / h95 / p73 / pb52 / y96）。

| 量 | 数值 |
|----|------|
| 仅唇变化的 \|dF1\| 均值 | **51.7 Hz** = 语料内 F1 标准差（164.0 Hz）的 **31.5%** |
| 仅唇变化的 \|dF2\| 均值 | **310.7 Hz** = 语料内 F2 标准差（576.2 Hz）的 **53.9%** |
| 归一化 F1/F2 比 | **0.58** |
| 配对 dF1 的 t 统计量 | **t(8) = −0.68**（临界 2.26）→ **与 0 不可区分** |

比值 0.58 说明**唇主要加载在 F2 上、其次 F1**，这正是拆分所依赖的断言，
而且它来自共振峰测量本身，不是来自模型。

**诚实附注**：t(8) = −0.68 是**非结果**，不是"无效应"的证据；
9 对只覆盖 3 个不同的配对（i/y、e/ø、ɛ/œ）。

### 5.3 旧 `lip_open` 主要是舌高代理（支持拆分方向的独立证据）

`lip_aperture` 与 `dorsum_y` 在 16 个被测元音上 **r = −0.955**。
这是不依赖声学的、直接的证据：旧的单轴大部分在编码舌体高度，而不是唇几何。

### 5.4 死轴审计：10 个坐标里 0 根是死的

`tools/audit_tongue_axes.py`，同一把尺子同时给新旧两套打分。

**新基（10 坐标，133 行）：**

- **literally dead（`n_distinct ≤ 1`）：0 根。**每根至少 4 个取值。
- **tier C（var / 最响坐标 var < 0.05）：4 根** —— `tip_x`(0.018)、
  `tip_y`(0.037)、`blade_x`(0.019)、`root_x`(0.004)。
- 语料子集（112 行）上多一根：`dorsum_x`，比值 **0.046**（全表 0.056），
  **横跨 0.05 阈值两侧，是阈值敏感项，不要当稳定结论引用**。
- 最小对立对数：`blade_y` 97、`dorsum_y` 48、`dorsum_x` 5、`root_y` 2，
  `tip_x / tip_y / blade_x / root_x` 各 **0**。

**旧 16 维，同一把尺子，全 133 行：tier C = 0**，语料子集也是 0。
最平的旧轴 `tongue_root` var/最响 = **0.0511**（语料子集 0.0709），
**只以 0.0011 越过 0.05 那道线**。

**因此："旧方案有 4 根死轴"这句话不是一把尺子下的测量结果。**它说的是
`fit_metric16.py` **按构造钉住**了 `tongue_root / glottal_tension /
larynx_height / lateral_ratio` 这四根，且旧审计只在 Phatak 的 16 个辅音上打分，
不是全部 133 行。诚实的表述是：**在这把方差尺子上，新 4 : 旧 0**。
JSON 里同时存了 `n_distinct / n_off_modal / var / rel_var`，
换任何一把尺子都能重算。

### 5.5 `place = 0.00` 过载已解决（实测）

舌坐标不需要这个拐杖：

- 10 个卷舌段（`ɖ ɖ͡ʐ ɭ ɳ ɻ ɽ ʂ ʈ ʈ͡ʂ ʐ`）`tip_x` 全部 = **0.30**
- 33 个央元音/滑音 `tip_x` 全部 = **0.20**
- **共享取值：0 个**

即"后缩下压的舌尖"与"静息舌尖"在第一根坐标上就是两件事。

### 6.1 最严重：辅音声学盲区，舌坐标的死轴风险完全未测

`fit_tongue_forward.py` 背后的 9 个共振峰语料**全是元音**。
因此 §5.4 的全部等级只是**发音学测量**，没有一根对着辅音声学核对过。

音节性：元音子集里 `root_x` 与 `root_y` **在 9 个特征中恒定**
（`vowel_cfg` 不动 root），最小范数解给它们的系数是任意的，
脚本对恒定坐标明确打印 `CONSTANT -- coefficient is meaningless`。
**这是元音子集的性质，不是坐标死的证据**——元音不做舌尖与舌根手势。
要判定这件事需要辅音数据。

**本轮取到的辅音数据（`tools/data/consonant/`）不足以判定：**

| 指标 | 数值 |
|------|------|
| 网络尝试 / 成功 | 1060 / 66 |
| 取回字节 | 154.9 MB |
| 打开的表格文件（DataverseNO） | 914 |
| 严格筛选后接受 | **2** |
| 覆盖的辅音音位 | **7**（`l b d g k ɣ ʝ`），3 种语言 |

**唯一有价值的辅音测量**：emudata `stops10.rda` 的 72 个爆破谱
（b/d/g 各 24，单一德语男声，16 kHz），爆破后 10 ms 取样，129 个谱 bin：

| 音 | 平均峰值 bin | 逐词标准差 |
|----|------------|----------|
| b | **8.1** | 8.3 |
| g | **28.5** | 13.1 |
| d | **47.1** | 18.8 |

### 6.2 10 个坐标不是单射：133 段塌缩成 66 条轮廓

> **部分已改善**（§0）：补上 `periodic` 与 `source_tilt` 后，摘要层唯一向量
> 由 66/133 升到 **117/133**，秩满 10/10。下文「67 段共享轮廓」是**只含
> 几何**时的数字，几何层本身仍不单射——这正是要把它移出距离基的原因。

**这是比等级更严重的缺陷。**

- **133 段 → 66 条 distinct 轮廓**；67 段与别的段共享轮廓。
- 语料子集：64 条签名覆盖 112 段，**72 段（64%）落在碰撞组里**。
- 例子：`p b pʼ ɓ ɸ ʘ ʙ β` 共用一个签名 `(tip 0.20, blade 0.15,
  dorsum 0.33, root 0.25, lip_open 0.0, lip_round 0.0)`（8 合 1）；
  `k kʼ k͡p xʼ ɠ ɡ ɡ͡b` 7 合 1；`ɕ ʑ` 完全同签名；
  `ʃ ʒ ɧ` 同签名；`ʈ ɖ ʈ͡ʂ ɖ͡ʐ` 同签名。
- 只保留 6 个"能分开"的坐标（blade_y, dorsum_x, dorsum_y, root_y,
  lip_open, lip_round）后仍是 66 条签名——**滤掉低对比坐标没有改善任何东西**。

**诚实定性**：碰撞组内各段的差异（清浊、送气、挤喉、时长）本就该由
`tongue_table.py` 额外携带的 velum / lateral / larynx / duration 吸收，
所以**轮廓签名相同是预期内的，不是轮廓模型的缺陷**。
但由此得到的结论是硬的：**这 10 个坐标单独不足以构成替换基**。

### 6.3 结构性冗余：有些坐标任何数据都分不开

`determined_by` 字段（全 133 行与 112 个语料行上结果相同）：

```
blade_x ← tip_x
blade_y ← blade_x, tip_x, tip_y
root_y  ← root_x
```

即 `blade_x` 被 `tip_x` 完全决定，`blade_y` 被另外三个决定，
`root_y` 被 `root_x` 决定。**这一类冗余不是数据不够，是不可能被任何数据分开
——包括将来才采到的数据。**这是 J1 意义上真正的失败，与 §5.4 的低对比
（那是"数据可能不够"）性质不同。

### 6.4 链中性被主动放弃（J5 不通过，且不修）

`gen_tongue_model.py` 原本要测的是**相邻部位锚点的导出位置是否等距**。
9 个由舌做收缩的锚点上实测：

```
dental 0.10 → alveolar 0.18 → postalveolar 0.25 → retroflex 0.28
→ palatoalveol 0.30 → palatal 0.36 → velar 0.45 → uvular 0.52
→ pharyngeal 0.70 → epiglottal 0.80
步长 = [0.08, 0.07, 0.03, 0.02, 0.06, 0.09, 0.07, 0.18, 0.10]
min 0.0200  max 0.1800  mean 0.0778  ratio 9.00
```

**比值 4.00，不是链中性要求的 1.00**（v8 的手调部位链是 12.5）。
**这是故意不修的**：等距要求锚点铺在一条均匀的链上，而真实的腭顶不是均匀的
（龈后到硬腭只有 0.05，硬腭到软腭有 0.20，差 4 倍）。要让比值回到 1.00，
就得让模型对解剖说谎。本文选择保住解剖、放弃等距，**代价写在 §6 的损失清单里**。

**顺序不单调的缺陷已修**（原 6.5 之前的一节，此处保留记录）：
`ANCHOR_CFG['palatal']['dorsum']` 的 x 写成 0.25，与 `postalveolar` 的 blade 同坐标，
使 `/ç/ /c/ /ɟ/ /ɲ/ /ʄ/ /ʎ/` 与 `/ʃ/ /ʒ/` 收缩点重合，`/ɕ/` 与 `/ʃ/` 也因此重叠。
修法是 palatal dorsum 移到 **0.36**，序列变为严格递增。这个缺陷由 136 个子代理的
逐符号审核查出，机械复算见 `tools/audit_symbol_assignments.py`，报告见
`docs/SYMBOL-AUDIT.md`。

> 注意这**不影响** §6.5 的腭沟结论：`ɕ`(0.30) 与 `ʃ`(0.25) 本来就差 0.05，
> 分开它们的是部位坐标，不是腭沟——加沟的分离增量仍是 0.000 cm。

### 6.5 腭沟（`ɕ` vs `ʃ`）：结论是**否定的**

`tools/gen_groove.py` 在轮廓上实现了第五个控制点 `groove_depth`
（默认 **5 mm**，`[假设]`，本仓无影像来源），两种解剖读法都测了
（blade–dorsum 之间凹陷 / tip–blade 之间凹陷）。

| 量 | blade_dorsum | tip_blade |
|----|-------------|-----------|
| ɕ vs ʃ 基线 Hausdorff | **0.786 cm** | 0.786 cm |
| 加沟后 **分离增量** | **0.000 cm** | **0.000 cm** |
| ɕ vs `t`（不同部位） | 1.644 cm | 1.644 cm |
| ʃ vs `t͡ʃ`（同部位不同方式） | 0.424 cm | 0.424 cm |
| 请求深度 → 实际实现 | 0.50 → **0.183 cm** | 0.50 → **0.360 cm** |
| 凹陷数（ɕ 平 / ɕ 加沟） | 1 / 1 | 1 / **2** |

**判决：`not earned at 5.0 mm depth`。**

四条要说清楚的话：

1. **交接前提被实测推翻**：ɕ vs ʃ 在四点模型里已经相距 **0.786 cm
   = 0.59 个平均部位步距**（平均步距 1.332 cm）。它们**是弱序，不是不可分**。
2. **真正缺的是方式，不是部位**：ʃ vs `t͡ʃ` 只相距 **0.424 cm**，
   而旧表里这两段只在 `tip_shape` 与 `duration` 两根轴上不同。
3. **字面判据本身是错的**：要求"同部位的 ɕ/ʃ 距离大于不同部位的 ɕ/t 距离"，
   等于要求龈后并入齿龈。脚本原文就是这么写的：
   `literal_criterion_groove_gt_unrelated = false`，并附
   `literal_criterion_note` 说明该判据不可能被满足。深度扫描
   0–15 mm 显示 7.5 mm 以下增益恒为 0.000，**没有任何深度能让它成立**。
4. **Phatak-08 无法回答这个问题**：那份 16 辅音清单
   （`p t k f θ s ʃ b d g v ð z ʒ m n`）**不含 `ɕ`、`ʑ`、`t͡ʃ`**。
   交叉核对能说的是反向的：唯一实测到的咝音**部位**步距
   `ʃ/s` = 0.0125，只有**清浊**步距 `ʃ/ʒ` = 0.0630 的 **1/5**；
   `ʃ/t` = 0.00027，全表非对角均值 0.0147。
   **唯一可用的混淆语料甚至不把部位排在清浊之前**，更谈不上支持一个咝音下的次部位对立。
   另外，`per_snr` 的 `ʃ→s / ʃ→ʒ / ʃ→t` 在 12/6/0/−6 dB 四档上
   **概率完全相同**，这份语料不携带任何 SNR 信息。

**处置**：沟作为**轮廓特征**保留（tip_blade 读法确实造出了第 2 个凹陷），
**不作为一根距离坐标**。它不在 `tongue_table.json` 的 10 维里，
因此 `audit_tongue_axes.py` **没有审计它**，它的死轴风险未测。

### 6.6 扣音（click）不可表达

舌体模型对非肺气流机制**没有表达力**。`derived_constriction` 里唯一处理
非舌动作的是"闭唇压过一切"这一条（为了双唇）。
内爆、喷音、搭嘴声门塞音靠的是**喉位与声门**，不是舌面几何；
旧表用 `airflow_direction` + `glottal_aperture` 承载，
新表里前者被降为标签、后者**没有对应坐标**。
**结论：舌体模型覆盖了 133 段里的元音与肺流辅音，
但不能区分同一舌位下的 ejective / implosive / 声门化塞音**——
它们的轮廓相同，只有 `larynx` 字段（3 个取值）不同，而该字段不参与距离。

### 6.7 其它已知未决项

- **21 行从未被任何语料证实**（`fʼ k͡p k͡x p̪ sʼ xʼ ŋ͡m ǀ ǁ ǂ ǃ ɠ ɡ͡b ɰ ʄ ʙ ʛ ʟ ʢ θʼ ⱱ`），
  它们的等级只靠设计上限撑着。
- **`retroflex` 锚点不在 `TONGUE_ANCHORS` 里**：`derived_constriction` 返回
  `x = 0.28, gap = 0.3571`（blade 在 0.60，roof(0.28) = 0.9571，不是接触），
  所以它被判为"舌不做收缩"，却仍然被表使用。**这是已知的不一致。**
- **`labiodental` 的导出收缩点落在 `x = 0.72`（舌根）、`gap = 0.402`**——
  导出函数在这个锚点上给出的是错误答案；表里靠 `CONSTRICTOR = None`
  与 `derived_site()` 的 0.05 门把它挡掉了，但导出函数本身没修。
- **`glottal` 锚点返回 `x = 0.66, gap = 0.035`**（贴着 0.05 门），同样被挡掉。
- **颚-舌位置的方差分解**（§5.2 之外被要求的那一项）**不可辨识，因此没有数字**。
  9 个语料里没有任何一个独立于舌高地改变颌或喉。替代的可测量结果只有：
  {jaw_open, larynx_height, lip_aperture, dorsum_y, lip_round} 这一块在
  16 个元音上**秩 4 / 5**，`larynx_height` 与 `jaw_open` 的 **r = +1.000**
  （没有元音携带发声手势）；把辅音段的发声手势放进来，秩回到 **3 / 3**。
- **`rounded_flag` 回归故意不作为结论**：`R²` 为 F1 0.0136 / F2 0.0047 /
  F3 0.0580，但这个标志与"抽到哪一对"共线，F2 的 0.0047 会被误读成
  "唇什么也不做"。JSON 里保留了它并带 caveat，**没有删，也没有引用**。
- **最小对立对数是地板不是判决**：一个稠密的物理描述按构造就会同时动多根坐标，
  所以 133 行里不存在隔离单根坐标的严格最小对。等级由方差型度量决定，
  因为它不需要最小对存在（`blade_y` 动 106 行、有 97 对隔离它）。

### 8.1 关于 57 个钉值

`docs/ALIGNMENT.md` 的钉值表是 16 维度量上的**精确数值**（如 `ã~an` = 1.156、
`pa~a` = 6.15、`abandon~adonban` = 12.78），由 `tools/test_alignment.py` 的
57 项检查守着。**新维度基下它们全部失效，没有一个可以复用**：

- 吸收的**锚定锁**（`|b1[k]| ≥ 0.3`，`IPA2VEC_ABSORB_TAU`）是逐维判定，
  `lips_closed → tip_x/tip_y`、`body → dorsum_x/dorsum_y` 的语义换轴会改变
  哪些维度算"锚拥有"；
- **锚手势门**（`locked > 1.0` 拒绝）的阈值是 16 维权重下的数字；
- **莫拉费率** `IPA2VEC_CONTOUR_MORA = 1.0` 与度量自身的 duration 权重 5
  耦合（M1 的全部论证），新基的维度数变了，权重必须重拟合。

`docs/ALIGNMENT.md` §「M1」还记录了一个不能重蹈的坑：duration 权重 5→1.0
会让 8 个对齐钉值偏移、度量空间 3 个最近基回归（`β̃→m`，因为鼻化擦音的
`vel_open = 0.6` 恰好卡在 `β(0)` 与 `m(1.0)` 之间，需要 `w_dur ≥ 3.7` 才保住 `β`）。
**这条记录说明重算不是机械重跑，必须连同它一起重新验证。**

### 8.2 现在**不该**做的事

- 不该重新拟合 16 维权重来"适配"新坐标——那是把新表塞回旧度量的形状里，
  会掩盖 §6.2 的塌缩。
- 不该把 `groove_depth` 加进距离基——§6.5 的判决是"5 mm 下不赚"，
  加进去只会多一根未被审计的坐标。
- 不该在 M0 完成前动 C 运行时——`voiced` / `glottal_*` 四个洞会让清浊、
  送气、紧喉、送气塞音全部坍缩，而这一点**现在**只有靠读代码才能发现，
  没有钉值会告诉你。
