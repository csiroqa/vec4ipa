# 逐符号赋值审核

本文记录一次对 `tools/data/tongue_table.json` 全部 133 个符号的系统性审核：
查出什么、哪些是真缺陷、哪些是审核本身的口径问题，以及修完之后剩什么。

复现：`python tools\audit_symbol_assignments.py`（机械复算）与
`python tools\gen_tongue_table.py`（生成）。

## 一、审核怎么做的

先由 136 个子代理并行逐符号检查六个方面，再由两个代理交叉复核。代理只负责提出
候选问题，**每一条结论都由 `tools/audit_symbol_assignments.py` 独立复算后才算数**。
代理报告 78 条，复算后确认 3 类真缺陷、1 类口径问题，其余为代理的过度解读。

六项检查：

| # | 内容 |
|---|---|
| 1 | 解剖越界：任一舌体点高于 `roof(x)`（舌头穿过腭顶），或 x 越出声道 |
| 2 | 部位序列：`derived_x` 沿 IPA 前后序严格递增 |
| 3 | 方式档案：`velum`/`lateral`/`larynx`/`duration`/`gap` 与 manner 相符 |
| 4 | 来源标记：`site_from` 声称的来源与几何实情一致 |
| 5 | 收缩载体：`constrictor` 与锚点声明一致 |
| 6 | 内部矛盾：`nasal` 却 `velum=0`、时长为负、状态越界 |

## 二、确认的三处真缺陷

### 1. 硬腭音的收缩点写在了龈后音的位置

`ANCHOR_CFG['palatal']['dorsum']` 的 x 写成 **0.25**，与 `postalveolar` 的
blade 同坐标。结果 `/ç/ /c/ /ɟ/ /ɲ/ /ʄ/ /ʎ/` 与 `/ʃ/ /ʒ/` 在收缩位置上完全重合，
**`/ɕ/` 与 `/ʃ/` 也因此不可分**——而这正是把 palatal 写进锚点表要解决的那个问题。

修：dorsum x 改为 **0.36**，y 由 `roof(0.36)` 计算而非硬编码。

修后部位序列严格递增：

```
0.00 双唇 → 0.05 唇齿 → 0.10 齿 → 0.18 齿龈 → 0.25 龈后
→ 0.28 卷舌 → 0.30 龈龈 → 0.36 硬腭 → 0.45 软腭 → 0.52 小舌
→ 0.70 咽 → 0.80 会厌
```

卷舌的 0.28 落在龈后与龈龈之间是对的：卷舌的舌叶抵在齿槽嵴之后，舌尖后缩到它后面。

### 2. 唇部与喉音的收缩点落到了静息舌根

`CONSTRICTOR` 里 `bilabial`/`labiodental`/`glottal` 没有舌载体，这是对的——它们本来
就不是舌的动作。但 `derived_site` 在这种情况下仍然去扫描舌面轮廓取最近点，而静息时
**舌根距咽壁只有 0.402**，于是：

- `/f/ /v/ /p̪/ /fʼ/ /ʋ/ /ɱ/ /ⱱ/` 的 `gap` 全部是 **0.402**，而摩擦音档案是 0.14
- **`/p̪/` 和 `/ʔ/` 这两个塞音因此完全没有闭塞**，gap=0.402

修：唇部锚点改用 `LIP_SITES` 直接给位（双唇 0.00，唇齿 0.05），`gap` 取方式档案值；
喉音仍无收缩位，但 `gap` 取档案值，于是 `/ʔ/` 闭到 0.0、`/h/ /ɦ/` 保持 0.4。

### 3. `assigned` 分支的 x 与 gap 取自不同器官

`derived_site` 的 `assigned` 分支从 argmin 取 `gap`、从指定部位取 `x`。对 `/ʐ/` 这
两处不是同一个器官：存的 `x=0.28` 是 blade，存的 `gap=0.402` 是静息舌根，而 blade 处
的真实 gap 是 0.450。

修：`gap` 一律在指定部位上按 `roof(x) - y` 计算。

## 三、审核自身的两处口径问题

这两条不是表的缺陷，是第一版检查写错了，记下来免得再犯：

- **元音被误判载体不符（33 个）**：`CONSTRICTOR` 里没有 `vowel` 这一项，元音不是收缩
  类别，检查却拿它当映射表查，于是全部报不符。元音的载体是 dorsum，单独处理。
- **接触高度差千分位被当成解剖越界（7 个）**：表格坐标存到 3 位小数，由 `roof()` 算出
  的接触高度四舍五入后可能比精确值高半个千分位。判定容差应当对齐存储精度（1e-3），
  高于它的才是真越界。

## 四、修完之后


`site_from` 分布从 57/66/10 变为 **derived 48 / assigned 82 / none 3**——`none` 只剩

## 五、这次修复没有改善检索指标，如实记录

| 指标 | 修复前 | 修复后 |
|---|---|---|
| Gate 1 部位/手法格 hit@1 | 0.3696 | 0.3696 |
| Gate 1 清浊对应误取 | 6/16 | 6/16 |
| LOCO act_prec | 0.5037 | 0.5089 |
| Spearman ρ | 0.3052 | 0.3081 |

**修的是正确性，不是分数。** 三处缺陷影响的是唇齿音、喉音、卷舌与硬腭音，而 Gate 1
用的 Phatak 16 音里没有 `ɕ ç ʐ f p̪ ʔ`，所以部位格分数不动是可预期的——**原先的
0.3696 是在错误坐标上测的，现在这个 0.3696 才是真的**。

## 六、代理报告中我未采纳的部分

- 「`/p/` 的 `site_from` 标 derived 但 `constrictor` 为 null」——双唇闭合由唇部参数表达，
  舌体停在静息位是应有的，不是错
- 22 个元音的 `derived_x`「无参照区间」——元音坐标落在 0.22–0.44 的合理范围，属无法判断
  而非缺陷

代理的用处在于第 2 类：它指出「`p̪` 是塞音却没有闭塞」，这条我复算后确认成立，且成因
是生成器的 fallback 分支整体取错，不是逐行录入错。**这类系统性缺陷逐行核对看不出来。**
